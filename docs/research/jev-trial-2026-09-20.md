# Jev routing trial: 2026-09-20

Six live requests completed through Vercel AI Gateway. Jev distinguished a known cache fix from a complex distributed race and abstained when the task lacked an outcome. No workers were run, so this establishes integration behavior, not routing accuracy.

The initial comparison used expectations invented by the evaluating agent. The user correctly rejected those as ground truth: Jev is intended to improve on agent judgment. The reported “four of six” agreement is not an accuracy score; the runner no longer scores agreement with those guesses.

## Live results

| Task | Jev selection | Choice probability | Confidence | Seconds |
| --- | --- | ---: | ---: | ---: |
| One README typo | Luna / max | 0.46 | 0.36 | 0.599 |
| Known-pattern CLI pagination | Luna / max | 0.36 | 0.23 | 0.433 |

The calls averaged **0.502 seconds**, totaling **16,957 input tokens** and
**473 output tokens**. Gateway returned **$0.00 total cost** for these requests;
this is an observed charge, not a promise about future pricing. Confidence was
returned separately from choice probability. Neither is a measured probability
that the selected worker will complete the task successfully.

Five candidates remained eligible under the public-context trial:
`codex/gpt-5.6-luna/max`, `codex/gpt-5.6-terra/max`,
`codex/gpt-6-astra/high`, `claude/claude-opus-5/high`, and
`claude/kimi-k3[1m]/max`. Grok and Fable routes were excluded by the current
local gates, so this run cannot compare their selection behavior when available.
The launcher set was `codex,claude,grok,claudex`, for comparison only; this run
made no worker launches and did not prove that the current agent could launch
every surface.

## What the selections establish

The pagination and visual-design selections differed from the evaluating agent's predictions. That says nothing about which selector was better. Compare actual task completion, quality, quota/cost and latency to evaluate routing; an agent baseline is a comparator, not the answer key.

The two cache cases shared the outcome text “Fix the cache.” Their different
facts and acceptance criteria produced different capability selections. That is
useful evidence that the additional context matters. It is one pair in one run,
not a controlled ablation or repeatability study.

## Conditions and reproducibility

The successful run used **public context**: builtin public candidate profiles,
synthetic task descriptions and routing preferences, plus anonymous live quota
summaries. It did not send private preference text or candidate overrides.
Local disablement/removal and runtime eligibility still applied. Expected
models/efforts and their rationale were recorded before requests, saved
separately, and excluded from Jev's input.

Gateway's **Zero Data Retention requirement was not requested** on this run.
The helper initially required it, but a live 403 established that Gateway
restricts that option to Pro/Enterprise plans. The option is now explicit as
`--require-zdr`. This run therefore does not validate ZDR behavior or Jev's
compliance with the user's complete private routing policy.

Command used:

```sh
python3 skills/model-routing/scripts/jev_trial.py --repo . \
  --launchable-via codex,claude,grok,claudex --quota-axi \
  --public-context --live \
  --output .furanku-skills/model-routing/jev-trial-public
```

Local request/expectation snapshots and `results.json` are under that output
directory. Results include request hashes. Subsequent runs refresh quota, so
eligibility and results may differ. The scripts never launch selected workers.

## Setup findings

The first attempts failed with `customer_verification_required`: Vercel required
a payment card on the key's team even for free-credit requests. Once the user
completed verification, the next attempt exposed the separate ZDR plan limit.
No model answers or cost metadata were returned for those failed requests.

The client now recognizes the verification error with a fixed actionable
message, without echoing arbitrary provider error bodies. Its regression test
failed before the change and passed afterward. ZDR remains available explicitly
rather than preventing public-data trials on Hobby plans.

## Decision

The integration works for typed recommendations and supports further trials.
Keep it opt-in: six cases, one run, low confidence on several cases, and no
worker-outcome validation are insufficient for automatic default routing.
Next evidence should include repeat runs and real task completion, with the
intended preferences and a representative available candidate set. This report
records the exploratory run before the opt-in production selector was added.
