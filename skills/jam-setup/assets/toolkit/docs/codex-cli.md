# Codex CLI image delegation

Use the installed Codex CLI to run an image-capable agent from another harness. `codex exec` is the direct local route; an orchestrator is optional. This invokes Codex's built-in image tool. With ChatGPT sign-in it uses the plan's allowance; with API-key sign-in it uses API billing, outside the toolkit's supported ledger. Treat API-key mode as an integration gap under the shared [cost boundary](images.md#cost-and-custody). The imagegen skill's Python API fallback is a separate route and requires explicit selection.

## Discover and run

1. Read the installed CLI's `codex --version`, `codex exec --help` and `codex login status`. Check its image-generation skill and, when needed, `codex features list`. An enabled feature or installed skill is preliminary evidence; the launched agent must have a callable image tool. Report missing installation/sign-in as setup work and give human-only sign-in instructions before asking for readiness.
2. Follow the host's model/account routing rules and the shared [cost boundary](images.md#cost-and-custody). Apply any routing decision’s account/environment binding to the launch, including its required environment removals; use the routing skill for that contract rather than copying a profile from this example. Reuse the selected authenticated profile without copying credentials or changing account settings. ChatGPT sign-in and API-key sign-in have different usage bases; report the mode only. A capability-only agent turn can inspect its tools without generating anything; it still consumes agent usage.
3. Create a unique output directory under `Art/.scratch/style/<round>/`. For independent style options, follow [style-image execution](style-images.md#independent-images-independent-sessions): one fresh `codex exec` per image, each with its own `<candidate>/brief.md` and output directory. Give the worker only the agreed common context/references, its single candidate direction, one-image allocation, output location and custody instructions; keep sibling candidates and coordinator history out of its input. For `jam-style`, dispatch only after the [round go-ahead](style-exploration.md#confirm-the-round-before-generation); include the authorized scope excerpt for that candidate and the attributable request/prerequisite-answer references from [task intent](task-intent.md) in the handoff, and require the worker to stop if either is missing. Supply reference files through `--image`/`-i` as documented by the installed CLI; a filename in prose does not attach an image. Because `-i` takes multiple values, keep the prompt separate: repeat `-i` per file and pass the prompt on stdin, or put the positional prompt after `--`. Name the parent as notification owner and constrain the worker to image work and its own output directory.
4. For each independent style candidate, start a new top-level `codex exec` (no `resume` or `fork`); an edit of a selected image may reuse its own session. Run with the project working directory, the normal approved sandbox, and a quoted prompt or stdin. Use `--json` when the caller needs structured events and `--output-last-message` for the final report. Both are text outputs; neither flag is the generated image destination. For gameplay-style rounds, the worker request and final image prompt must carry the [believable-gameplay and semantic prompting rules](style-images.md#translate-the-brief-into-visible-instructions). Ask the agent to use its built-in image tool and copy its actual generated file into its candidate directory following the installed imagegen skill. Require it to report tool absence or failure without switching to a billed API or fabricating an image.
5. Wait for the owned process to finish, inspect its exit status and final report, then verify and view the returned images yourself. Corroborate the reported origin against available invocation evidence, such as the copy from built-in image storage and any executed API scripts. Some CLI versions omit image-tool events from JSON output. When available, locate this invocation’s session rollout under the selected Codex home using its session ID. Inspect only that invocation’s image generation records to corroborate prompts, image inputs and output paths; event schemas vary by version. Keep private transcripts in ignored scratch and extract only necessary art provenance. State any remaining evidence limit rather than inventing a tool event. Record origin and prompt/input roles under the shared [custody rules](images.md#cost-and-custody). If the process loses its response, inspect that invocation's events and output files before considering another generation. A zero exit code or a report saying “generated” is not image evidence.

One-candidate example once the conversation authorizes the round; a separate confirmation exchange is not required. The coordinator prepares `A/brief.md` with the complete shared gameplay-frame specification (camera, actor scale, play situation/layout, presentation and aspect ratio), only A's visible art treatment, and the **exact final image prompt** under a separate heading. Keep one-image scope/cost and the actual authorization reference outside that prompt. Follow [prompt preservation](style-images.md#preserve-the-image-prompt-through-delegation): the worker executes the concrete prompt instead of reauthoring the art direction. The record must identify the real decision, not an agent-invented approval. Repeat with a **new invocation** and separate B/C/D briefs for the other authorized candidates (adapt paths; model/profile flags follow host routing). For a character/outfit study, substitute its requested subjects and framing; do not copy the gameplay-camera assignment into it.

```sh
codex exec --cd . --sandbox workspace-write --json --output-last-message Art/.scratch/style/round-01/A/result.txt 'Read Art/.scratch/style/round-01/A/brief.md for your single approved candidate, exact final image prompt and attributable authorization. If authorization or the prompt is missing or mismatched, report and stop without generating. Follow tools/jam/docs/style-images.md. Use $imagegen and its built-in tool to generate exactly one image for candidate A with the supplied image prompt. Preserve its creative content; required tool formatting must not change subjects, count, outfits, pose, camera, scale, reference roles or treatment. Use only the assigned context and approved references, not sibling candidate files or prior candidate conversations. Parent owns notifications; send none. Copy the original image into Art/.scratch/style/round-01/A/ and report its path, exact prompt sent, actual image inputs, tool, session ID if available and visible deviations. If the tool fails or is absent, report and stop; no retries, API fallback, installs or configuration changes.'
```

Use literal shell quoting so `$imagegen` reaches the agent unchanged. Handle file paths with spaces through the calling shell's normal quoting. When saving is blocked, retain the actual generated path and report the restriction; use an authorized file transfer or permission flow instead of silently weakening the sandbox. Keep private execution logs in scratch, not versioned provenance.

## Evidence

Official [CLI commands](https://learn.chatgpt.com/docs/developer-commands#codex-exec) document non-interactive agent execution, image inputs and result capture. Official [image-generation guidance](https://learn.chatgpt.com/docs/image-generation) documents built-in CLI generation. Local execution evidence is recorded separately in the review; documentation alone does not establish that every CLI version, account or host exposes the image tool.
