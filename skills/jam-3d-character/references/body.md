# A rigged character

How to make one rigged character, player or NPC, on Epic's UE5 Mannequin skeleton: generate, repair the fingers when needed, quad-remesh, unwrap, texture, rig, export. The character is one mesh unless the game swaps its pieces; [swappable parts](#swappable-parts) is the branch for that. The rules in [SKILL.md](../SKILL.md) apply throughout; outfits for the body follow [outfit.md](outfit.md); [scripts.md](scripts.md) lists what each script takes, writes and assumes. Figures quoted below (credits, failures, measurements) are observations from the first body made with these scripts.

## Decide before any image is made

Write each decision into the brief. Changing one later means redoing every stage after it.

| Decision | What to settle | Why |
| --- | --- | --- |
| Skeleton | Rig to the Mannequin's bone names, hierarchy, orientations and bind pose (`SK_Mannequin`), with the character's own bone lengths. Name the animation blueprint and animations the game drives the character with. | The character then uses the Mannequin's animations, foot rig and every bone the game's code reads, with no retargeting. |
| Proportions | Give target limb lengths in the brief, as shares of body height: shoulder to wrist, hip to ankle, hand length, foot length. Manny at 180 cm: shoulder to wrist 55 cm (0.31), hip to ankle 86 cm (0.47), wrist to middle knuckle 9.5 cm, ankle to ball of foot 17 cm. | Gameplay values tuned on Manny assume his proportions. The first body came out with arms 19% shorter and hands and feet a quarter shorter; seven gameplay tests then failed and the choice between retuning and reshaping fell to the user after delivery. |
| Parts | One mesh (the default), or swappable head, hair, body and hands when the game changes hairstyles or outfits on this body. Record it as `parts` in `character.json`. | Swappable parts add the split, a scalp built under the hair, borders moved onto the colour borders, and hands split off at the wrists so every outfit shares them. |
| Hands | Whether each finger must move: `hands.fingers` 5, or 0 for mittens that follow the hand bone alone. | Separate fingers constrain the references, need the finger repair step, and are what the rig's finger weighting expects. |
| Physics | Whether the character is grabbed, knocked over or falls as a ragdoll. | That needs a physics asset fitted to the body. The import scripts assign Manny's `PA_Mannequin`, whose bodies have Manny's proportions. |
| Budget | A profile in `jam.config.json` for the body (one material for one mesh; for swappable parts, 4: head, hair, body, hands); the first body used 20,000 triangles target, 30,000 limit, 2048 textures, 4 bone influences. | A crowd NPC may need a smaller profile; add one rather than loosening an existing one (changing a profile makes every run bound to it stale). |

## Steps

`$P $S/character.py run --character $W/character.json --work $W --joints <meshy-joints.json> --remesh <remesh model.fbx> --source <source model.glb> --manny <SKM_Manny_Simple.fbx>` runs the local stages below (transfer, class check, topology, UVs, textures, rig, export) in order, remembers the paths, skips stages whose inputs are unchanged, and stops at each review gate with its evidence; run it again after the review to continue. `--dry-run` lists the commands; `--from`/`--to` pick stages. The steps describe what each stage does and its done condition.

Work in `Art/.scratch/<asset>/<run>/` (called `$W` below). Every script that needs to know the character takes `--character $W/character.json`. Blender 5.1 was used. Each stage goes through the review procedure under the run's effective policy (`node tools/jam/jam.mjs status --run <run.json>`, `tools/jam/docs/review.md`); a human review goes through the catalog as [SKILL.md](../SKILL.md#rules-for-every-branch) describes.

0. **Character spec.** Write `$W/character.json` from the brief and the decisions above, as [character-spec.md](character-spec.md) describes: name, height, the body part, material classes and their roles, hands, `maxInfluences` from the project profile. Start from [`assets/character.example.json`](../assets/character.example.json). Colours are first taken from the concept and sampled again from the texture in step 6. Done when `$P $S/charspec.py $W/character.json` reports it valid.
1. **References.** Use `jam-concept`, then `jam-turnaround`.
   - Smooth, unfaceted surfaces in every image. Faceted references produce faceted textures and topology.
   - Arms held away from the body.
   - With `hands.fingers` 5: fingers relaxed and slightly apart, each visible in the front and back views, hands edge-on in the side views, and each view generated on its own at 1024×1536 (views cut from one sheet were 512 px wide and gave mitten hands; the mesh made from them was rejected, 30 credits). With `hands.fingers` 0, keep the approved hand design; finger visibility is not required.
   - Measure the proportions from the decision table on the front view and record them in the turnaround's evidence.
   - Done when the views are accepted and the measured proportions meet the brief.
2. **Mesh.** Use `jam-model`: Meshy multi-image-to-3D with 2k geometry (35 credits). Look at both hands in the result when `hands.fingers` is 5: generated hands often have fingers fused by shared faces on one side. Done when the mesh is accepted and you know whether any fingers are fused, and on which hand.
3. **Joints.** Run Meshy's rigging on that mesh task with the spec's `heightMeters` (5 credits), then `$B/meshy_rig_joints.py -- <rigged_character.glb> $W/rig/meshy-joints.json`. Only the joint positions are used, in metres at that height. Done when the file lists shoulders, elbows, wrists, hips, knees and ankles inside the body.
4. **Finger repair** (when fingers are fused or closer than about 9 mm, with separate fingers): set `hands.cleanSide` to the clean hand, then `$B/spread_fingers.py -- <mesh model.glb> $W/rig/meshy-joints.json <rig-scale> $W/spread --character $W/character.json`, where rig-scale is `heightMeters` divided by the mesh's height. It mirrors the clean half onto the other and fans the fingers apart. Done when `spread-report.json` shows `minGapAfterMm` of 9 or more between every pair of fingers and `verticesClaimedByTwoFingers` 0.
   - The later steps read two inputs: the high-resolution source `$SRC` (`$W/spread/model-spread.glb` after this step, else the mesh's `model.glb`) and the remesh input `$GEO` (`$W/spread/model-spread-geometry.glb` after this step, else the mesh task itself).
5. **Quad remesh.** Use `jam-retopo`: Meshy remesh, quad topology, target 10,000 faces (5 credits), of `$GEO`. Upload only the welded geometry-only file: a textured upload has its vertices split along UV seams and came back with about 2,000 open edges. Done when the result has no triangles, n-gons, open edges or non-manifold edges.
6. **Colour onto the remesh.** A remesh comes back rescaled, and from an upload without usable colour: `$B/transfer_color.py -- <remesh model.fbx> $SRC $W/transfer_base_color.png 4096 $W/model-aligned.fbx --character $W/character.json`. Then sample each class's `rgb` from clean areas of `transfer_base_color.png` into the spec. Done when the log reports every covered texel reached, a mean distance to the source under 1 mm, and the spec holds the sampled colours. Then check the classes: `$B/preview_classes.py -- $W/model-aligned.fbx $W/transfer_base_color.png $W/classes --character $W/character.json`; every class must cover what the design gives it, none empty, with a small ambiguous share (`classes-report.json` and its renders). Give metal materials `metallic` 1, or pass the provider's metallic map to the bake with `--metallic-map`.
7. **Topology.** `$B/export_parts.py -- $W/model-aligned.fbx $W/topology --character $W/character.json` names the mesh after the body part, then `node tools/jam/jam.mjs measure --file $W/topology/character-topology.glb` for the topology record. Done when the measurement is within the profile.
8. **UVs.** `$B/unwrap_parts.py -- $W/topology/character-topology.blend $W/transfer_base_color.png $W/rig/meshy-joints.json $W/uv --character $W/character.json`, then `$P $S/blender/draw_layout.py $W/uv`, `$B/render_checker.py -- $W/uv/character-uv.blend $W/uv/renders --character $W/character.json` and `$B/export_uv.py -- $W/uv/character-uv.blend $W/topology/character-topology.blend $W/uv`. Seams come from the anatomy (the joints), with material borders as extra cuts: neck and waist loops where no material border already runs, wrists, ankles, soles and hand outlines, a side seam from each wrist to the waist, the seat and inseams, the back of the head, and a cut through any island still a tube. The script exits with an error when the gate fails. Done when `uv-report.json` shows `gate.passed` true and the checker render shows even squares.
9. **Textures.** `$B/bake_textures.py -- $W/uv/character-uv.blend $W/transfer_base_color.png $SRC $W/texture --character $W/character.json`, then `$B/render_textured.py -- $W/texture/character-textured.blend $W/texture/renders --character $W/character.json` and `$B/render_hair_check.py -- $W/texture/character-textured.blend $W/texture/head --character $W/character.json --unlit`: base colour without lighting is where a texture fault cannot hide in shading. Done when the close-ups show no colour of one class on another at any border and no pale fringe along the hairline.
10. **Rig.** Export `SKM_Manny_Simple` and Manny's idle, walk and jog once with `$S/unreal/export_manny_reference.py` (see [engine checks](#engine-checks-before-the-delivery-review)); keep those files in scratch, they are Epic's. Then `$B/fit_rig.py -- $W/texture/character-textured.blend <SKM_Manny_Simple.fbx> $W/rig/meshy-joints.json $W/rig --character $W/character.json`; the rig stands at the spec's `heightMeters`. Body regions come from the joints; it stops with an error when the joints don't fit the mesh, when `hands.fingers` 5 finds fewer than four fingers or no thumb (repair the fingers, or set `fingers` 0), or when the deformation check fails (`rig-report.json` → `deformationCheck`).
    - Poses: `$B/render_pose.py -- $W/rig/character-rigged.blend $W/rig/poses bind`, then once per `--pose curl`, `reach`, `crouch`, `look`, and once per Manny animation with `--anim <file.fbx> --frames 1,8,16,24`.
    - Stretch: `<blender> --background --python $S/blender/edge_stretch.py -- $W/rig/character-rig-fit-pose.blend $W/rig/character-rigged.blend`.
    - Done when no edge stretches more than 2×, no face spans two fingers, the fist closes without crumpling (with separate fingers), and Manny's walk plays with the feet on the ground.
11. **Unreal files.** `$B/export_ue.py -- $W/rig/character-rigged.blend $W/unreal --character $W/character.json` writes `SKM_<name>.fbx`. Done when `export-info.json` lists exactly one UV set, `UV0`. Unreal samples textures through the first UV set in a file; the first delivery carried the remesh's old layout ahead of it and every texture came out scrambled in the engine.

## Swappable parts

When the game swaps hair, heads or outfits on this body, the spec lists `head`, `hair` (unless the head has none) and `hands` beside `body` ([`assets/character.parts.example.json`](../assets/character.parts.example.json)), and the main steps change as follows. Outfits for the body ([outfit.md](outfit.md)) need this branch.

- **After step 6, split:** `<blender> --background --factory-startup --python-exit-code 1 --python $S/blender/split_parts.py -- $W/model-aligned.fbx $W/transfer_base_color.png $W/split --character $W/character.json`, then project the colour again onto the mesh it moved: `$B/transfer_color.py -- $W/split/model-snapped.fbx $SRC $W/transfer_snapped.png 4096 $W/model-snapped-aligned.fbx --character $W/character.json`. Keep this split output from here on: two runs of the split differ slightly, and the second projection fits only the run it was made from. A split that stops because the hair class found no faces needs that class's colour or `hsv` window corrected. Done when `split-stats.json` shows `facesTurnedOver` 0, `arrowheadCornersLeft` 0, and with hair `scalpVertsWithUnsoundQuads` 0 and `worstThroughHairMm` under 0.5, and `$B/render_hair_check.py -- $W/split/character-parts.blend $W/check-split --character $W/character.json --flat` shows head and hair with clean borders from the left, right, front and back.
- **Steps 7 to 9** read the parts: `export_parts.py` takes `$W/split/character-parts.blend`, and `unwrap_parts.py` and `bake_textures.py` take `$W/transfer_snapped.png`. Each part gets its own UVs and maps.
- **After step 10, split the hands** (when the spec has a hands part): `$B/split_hands.py -- $W/rig/character-rigged.blend $W/hands/split.blend $W/hands/split-report.json --character $W/character.json --modelled $W/texture/character-textured.blend $W/hands/modelled.blend`, then `$B/bake_hands.py -- $W/hands/split.blend $W/hands/rigged-final.blend $W/texture --character $W/character.json --modelled $W/hands/modelled.blend $W/hands/modelled-final.blend`. The body is cut at an edge loop 1.5 cm above each wrist in the rigged and the modelled file alike; both sides keep the loop's vertices and weights, and the body's smooth normals are frozen as custom normals so the seam does not show on bare skin. Done when the report shows every hand border vertex matched on the body with weight difference 0 and `samePartsAsRigged` true, and close-ups of both wrists, unlit and lit, show no line.
- **Step 11** exports the final rigged file (`$W/hands/rigged-final.blend` when the hands were split) and writes `SKM_<name>.fbx` plus one `SKM_<name>_<part>.fbx` per part.

## Engine checks before the delivery review

Both checks come before the human sees the delivery. The first delivery passed the headless check and was approved with scrambled textures in the engine, because nothing had been rendered there.

1. **Headless import.** In a Unreal project that holds `/Game/Characters/Mannequins` (Epic's third-person template content), with `JAM_UE_DIR` naming a work folder outside every checkout and the FBX files in its `import/` subfolder and `JAM_UE_CHARACTER` naming the character's `character.json`, run `$S/unreal/import_check.py` and `$S/unreal/pose_check.py` with `<engine>/Binaries/<platform>/UnrealEditor-Cmd <project.uproject> -run=pythonscript -script=<file> -unattended -nosplash -nullrhi -stdout`. Write Blender's joints with `$B/joint_positions.py -- <rigged.blend> <anim.fbx> 1,40 $W/rig/verify/blender-MM_Idle.json` (and `1,8,16` for `MF_Unarmed_Walk_Fwd`), then `$P $S/unreal/compare_joints.py <ue-joints.json> <import-report.json> $W/rig/verify <out.json>`. Done when every file imports on `SK_Mannequin`, the root bone's scale is 1 and animated joints sit within a few centimetres of Blender's.
2. **Seen in the engine.** Copy the delivery's `unreal/` FBX and its texture maps to the same repository-relative path inside a game checkout, start that checkout's editor, set `delivery` in the CONFIG block of `$S/unreal/import_1_textures.py` to `import_4_save.py`, and run them through the editor's Python tool, one call each. Capture the mesh with the editor's `CaptureAssetImage`, or place it in a level and use the project's capture tooling. Done when hair, skin and every garment show their own colours and the shading has no inverted patches. Keep one editor open and stop it when the check is done.

## Delivery

Package as `tools/jam/docs/contracts.md` requires: a new revision folder under `Art/Assets/<asset>/`, self-contained, with a fresh `run.json` and `character.json` at its root (the Unreal import steps read `<delivery>/character.json`). Deliver the final files under fixed names: the rigged character and armature as `source/character-rigged.blend`, the character as modelled (straight arms) as `stages/texture/character-textured.blend`, the maps in `stages/texture/`, the Unreal files in `unreal/`; with swappable parts and split hands, the two `-final` files take those names. `$S/blender/relative_paths.py` and `$S/blender/export_glb.py` prepare the Blender files and the runtime model. Copy every script you ran into the delivery's `source/scripts/`. With swappable parts, the delivery's `README.md` names the files outfits read: `character.json`, the Meshy joints (`meshy-joints.json`), the parts as modelled and the rigged parts; the last two hold every part under the same object names and vertex order. A correction to an accepted revision is a new revision folder; records of files that are byte-identical to accepted ones carry that approval, and the changed stage is reviewed again.

## Putting it in the game

On a branch of the game, as its own change:

1. Run the game's tests on the unchanged branch and keep the result as the baseline.
2. Import with the four import steps above. Then run `strings` over the new `.uasset` files and confirm none holds an absolute machine path; the legacy texture and FBX factories the steps use store only a path relative to the project.
3. The character imports as one skeletal mesh on `SK_Mannequin` with its material and physics asset. With swappable parts, each part is its own skeletal mesh as well; register the body's pieces (head, hair, body, hands) with the game's outfit or wearable mechanism, and add or run a test that every piece of every outfit worn by this body has this body's reference skeleton.
4. Run the tests again and compare with the baseline. A test that fails only with the new character names a gameplay value tuned on other proportions: report it to that system's owner instead of changing the test.
5. Play it: start Play In Editor, drive the character with real inputs, capture the game view standing, walking, crouched and in every other pose the game uses, and run `$S/unreal/compare_bones_in_game.py` through the editor's Python tool. Then hand the branch to a person to play.

## Cost

One clean body is 45 Meshy credits: mesh 35, joints 5, quad remesh 5. The first body cost 120, with 75 spent on results that were not used: a mesh from low-resolution views, a mesh whose reference had merged fingers, a remesh with fused fingers and a remesh of a textured upload.
