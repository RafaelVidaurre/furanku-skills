# PRR Audit

Read when the main skill selects Audit. Inspect freshness, usefulness, authority, and record integrity; this procedure uses the canonical rules rather than redefining them.

1. **Bound the audit.** Identify the canonical project checkout, its revision and local changes, and the requested areas. Treat old worktrees as historical snapshots, not separate current products. For a portfolio survey, inventory projects and screen current entries before selecting evidence-backed cases; report coverage as a survey rather than claiming exhaustive validation. For a full record audit, include every current entry, its sources and detail links, and relevant annex states. Done when: the inspected scope and limits are explicit.
2. **Check discovery and use.** Apply the main skill's Read and use pointer requirement. Find task briefs, design choices, reviews, or acceptance checks that applied the record. Distinguish file reads from decisions they informed. Done when: there is evidence of consumption or a stated gap; a duplicate authoritative record or record without consumers has a consolidation/retirement recommendation.
3. **Screen usefulness.** Apply What belongs and Durable claim wording to each entry in scope. Identify its future product consequence and source support. Mark mixed entries for separation, duplicates for consolidation, and process/history/research for their proper homes. Retain legitimate detailed product boundaries. Done when: findings name what to retain, move, clarify, or retire and why, rather than calling entries merely vague or too technical.
4. **Check freshness and authority.** Apply the main skill's freshness classifications. Compare affected entries with later user decisions, related current entries, source exchanges, linked specs, and implementation evidence. Distinguish quoted user intent from agent inference, including scope added under broad quality goals. Check whether later decisions answer listed open questions or replace phase-specific policies. Done when: every suspected stale item has dated superseding evidence or is labeled uncertain; code differences alone remain implementation drift.
5. **Check integrity.** Read [record format](record-format.md). Resolve IDs, source references, detail links, cross-area pointers, index entries, and relevant state transitions. Preserve whole prior entries when replacing state. Done when: each inspected relationship resolves or has a concrete finding; missing evidence is not reconstructed from inference.
6. **Apply or route.** Repair mechanical drift within the requested scope. Apply already-authorized semantic changes using record format's Replacing current state; unresolved product choices use [Conflicts or Digest](maintenance.md). Moving a confirmed commitment out of PRR preserves its authority and traceability in the destination; it is not permission to delete the constraint. In a skill-improvement survey, report project cleanup candidates without silently changing those products. Done when: each finding is fixed, remains a reviewable cleanup candidate, or names the specific decision needed.
7. **Report.** Separate confirmed stale decisions, misplaced content, unsupported claims, implementation drift, and unknowns. Include the evidence, practical consequence, and recommended disposition. State checks performed and remaining coverage gaps. Done when: the user can distinguish a skill fix from a repaired project record and neither is presented as proof of changed future agent behavior.
