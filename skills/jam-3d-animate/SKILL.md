name: jam-3d-animate
description: Make or check an animation clip for a rigged humanoid character on the project's own rig. Defines the clip with the person (frame rate, length, loop, in-place or root motion, ground, key poses, acceptance thresholds), chooses a route the setup allows (keyed by hand in Blender, retargeted from an existing clip, or generated by a motion provider), puts travel where the spec says, and checks the clip for foot slide, ground penetration, jumps at its ends and loop seams, with a pose sheet and a video. Use when the user asks to animate a rigged character or make a clip such as a walk, run, idle or attack; to generate or retarget motion onto their rig; to check an existing animation clip; or when a recipe run reaches its animation steps.

# Animation clips

Four words carry this skill. The **clip spec** (`clip.json`) says what one clip must be, from the person: frame rate, length, loop, root convention, ground, key poses and the thresholds the check enforces. **Key poses** are named poses on the project rig at their times. A **route** is how the motion is made: by hand, by retargeting a clip that exists, or by a motion provider. The **clip check** measures any clip, however it was made, on the project rig against the spec.

A clip is a glTF binary (`.glb`) holding the skinned project rig and one named animation, in metres, +Y up, the character facing +Z, sampled on whole frames of the spec's frame rate. Engines convert it in their adapter, never here.

`<S>` is this skill's `scripts/` folder. Commands are written for a project with the jam toolkit, where `jam` is `node tools/jam/jam.mjs`, paths are project-relative and every script runs from the project root (when the toolkit is missing and wanted, use the `jam-setup` skill). Without the toolkit the same scripts run from the project root as `blender --background --python-exit-code 1 --python <script> -- <arguments>` and `python3 <script> <arguments>`; each script's header lists its arguments. They were written and run with Blender 5.1.

## Make a clip

1. **Define the clip.** Read [references/clip-spec.md](references/clip-spec.md) and settle every field with the person; a value they have not given comes from the project's own files or is asked for, never filled in. In a recipe run, `jam run next <id>` names the step's files.

   `jam python <S>/clip_spec.py <clip.json>`

   Done when it exits 0 and the person has accepted the spec. In a run: `jam run record <id> define --file spec=<clip.json> --note "<purpose; who set the thresholds>"`; the toolkit's `clip-spec` check holds it to the toolkit's schema, which is the spec's definition.

2. **Key poses**, when the spec lists them. In Blender, pose the project rig for each one and keep each pose as an action named exactly as in `keyPoses.poses`, in a `.blend` or `.glb` beside the rig (or as animations of `rig.model` itself). Then:

   `jam blender <S>/keyposes.py -- <clip.json> [--poses <file with the pose actions>]`

   It writes the spec's `keyPoses.file` (one key per pose at its frame) and a manifest beside it with the extension `.json`. Done when it exits 0 and the person has seen each pose on the rig and accepted it. In a run: `jam run record <id> keyposes --file keyposes=<keyPoses.file> --evidence <manifest .json> --tool "Blender <version>, jam-3d-animate keyposes.py" --note "..."`; without key poses, `jam run skip <id> keyposes --reason "..."`.

3. **Choose the route.** Read [references/routes.md](references/routes.md): list the routes this setup can actually call (Blender here, a source clip the project may use, providers whose descriptor serves `motion` in the mode the clip needs, probed this session), price each, and offer them with their cost; the person chooses. Done when the route, the provider and model or source, the expected cost and the person's choice are written down.

4. **Make the motion** by the chosen route (routes.md has each in full):
   - **by hand**: key it in Blender on the project rig from the key poses and export the `.glb`;
   - **retarget**: hand the source clip, its skeleton map, `rig.model` and `rig.map` to the `jam-3d-retarget` skill;
   - **provider**: load its page or skill, run a paid job through the ledger (`jam job open` … `jam job done`), keep the outputs untouched, and have `jam-3d-retarget` bring motion on another skeleton onto the project rig.

   Done when a `.glb` with the motion on the project rig exists (the check confirms the skeleton) and any job is settled. In a run, record the clip as the route returned it, `jam run record <id> motion --file clip=<clip> --note "..."` with the provenance routes.md lists for the route, then `retarget` as `jam-3d-retarget` says, or `jam run skip <id> retarget --reason "the motion is on the project rig"`.

5. **Put the travel where the spec says.**

   `jam blender <S>/root_convention.py -- <clip.glb> <clip.json> <out-dir> [--travel line|hips]`

   In-place takes the overall travel off the hips and keeps their bob, sway and turns; root motion puts the travel on `root.bone` (the hips keep the rest, every joint stays where it was) or leaves it on the hips. `--travel line` reads travel as a constant velocity (cycles); `--travel hips` follows the hips exactly (starts, stops, clips whose speed changes). It writes the clip and `travel.json`. Done when it exits 0 and `travel.json`'s `hips` shows it: for in-place, `after.alongRange` is the hips' own motion with the travel gone and `heightRange` unchanged; for a root bone, `overRoot` shows what stayed on the hips.

6. **Check the clip.**

   `jam blender <S>/clip_check.py -- <clip.glb> <clip.json> <out-dir> [--travel <travel.json> | --travel-velocity <vx>,<vz>] [--provider-contacts <file>]`

   An in-place clip needs `--travel` (the file from step 5) or `--travel-velocity` (`0,0` for a motion that never travelled), because its planted feet move with the removed travel. Without `contacts.detect` in the spec, add `--contact-height <m> --contact-speed <m/s>` from the person. It writes `clip-report.json`, `clip-sheet.png` and, when an encoder is found, `clip.mp4`. Read [references/check.md](references/check.md) for what each number means and what to do when one fails.

   Done when it exits 0 (`"passed": true`), every entry in `unmeasured` has been judged by the person from the sheet or video, and you have looked at the sheet and video and can state that the motion does what the purpose says, or which fault it shows. A failure goes back to step 4 or 5 through check.md's table; a threshold changes only when the person decides so.

7. **Deliver.** In a run, record the check, then (after any engine import) the delivery:

   `jam run record <id> check --file clip=<clip.glb> --file evidence=<out-dir>/clip-report.json --file evidence=<out-dir>/clip-sheet.png [--file evidence=<out-dir>/clip.mp4] --tool "Blender <version>, jam-3d-animate root_convention.py and clip_check.py" --note "<root convention and travel reading, anything unmeasured and the person's judgement>" --accept "<what you saw in the sheet and video>"`

   `jam run record <id> delivery --file clip=<clip.glb> --file evidence=<out-dir>/clip-report.json --tool "<the tool recorded at check>" --note "..."`

   The toolkit's `clip-report` check accepts a step only with a report that passed and measured the recorded clip. Putting the clip into an engine is the `jam-engine` skill's `import --kind animation`, when the adapter has it (`jam engine show`); otherwise the step is skipped. Done when the delivery is recorded; outside a run, when the person has the clip, `clip.json`, the report, the sheet and the video, with your finding.

## Check a clip made elsewhere

Any humanoid clip can be checked: write a spec for it with the person (step 1; `keyPoses` may be left out), with `rig` naming the skeleton the clip is on and its map. A clip meant for the project rig but on another skeleton goes through `jam-3d-retarget` first. Then step 6, with `--travel-velocity` for an in-place clip. Done as in step 6.

## What is validated

[references/validation.md](references/validation.md) lists every run with its numbers. In short: on generated walk cycles with faults of known size, the check read a planted foot's slide, a sunken foot's penetration (on the mesh and on joints alone), a pop at either end and an unclosed loop to within 2 mm, and passed the clean clip; the root convention removed travel while keeping the pelvis bob and sway, and moved travel onto a root bone with every joint left in place. One generated clip went through the whole `animation` recipe on a bound test humanoid: retargeted both ways, checked (the check caught the generator's foot drift and ground penetration), imported into an engine and delivered. Not validated: real characters, captured or library motion, the by-hand route, turning or terrain-crossing clips. The pure helpers have unit tests (`python3 -m pytest <S>/test_jamanim.py`); `<S>/test_animate_blender.py` runs the scripts in Blender on generated clips and is skipped without it.
