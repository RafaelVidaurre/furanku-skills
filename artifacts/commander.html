Commander

A standing delivery manager. It reads your Beads, splits them into fronts, and sends each front to the exact agent you configured for it.

It adds two decisionsBeads already holds the work and Orca already runs the agents. Commander decides the fronts and the routes — nothing else.
Everything is traceableEvery dispatched task carries the run key, Bead ID, front key, route ID and the exact agent, model and effort it was launched with.
Only when you askCommander never triggers itself. You invoke it by name to deliver, resume, report or configure.

The cast

Two systems Commander sits on top of, and three kinds of owner it works with.

Contract

Beads

The durable record. Outcomes, acceptance criteria, dependencies and decisions live here — not in the chat log.

Coordination

Orca

Terminals, worktrees, tasks, retries, results. Commander uses Orca's own task state and adds no lifecycle of its own.

Manager

Your session

The session you launched is Commander. It keeps its own model and effort — no route applies to it.

Owner

Captain

Takes a front that still needs breaking apart or putting back together. Runs its own Workers and returns one integrated result.

Owner

Worker

Takes exactly one bounded outcome. If a front needs more than one Worker, it was a Captain's front.

      Rules worth remembering

      One outcome, one owner

      A front is not a task list. If it has two outcomes, it is two fronts.

      Beads, not chat

      New requirements and decisions get written into the Bead as they surface, so the next run starts from the truth.

      Child Beads are rare

      Create one only when the child is a distinct durable requirement — not just a step in the work.

      Work bubbles up

      If a Captain finds Captain-shaped work beneath it, that comes back to Commander as a new front.

      Launch, then dispatch

      The terminal is launched with the exact route first; the task is dispatched to that handle second. Never the other way round.

      Worktrees follow dependency

      Child worktree for work stacked on another checkout; top-level for independent work. Sidebar nesting is not ownership.

      No second lifecycle

      Orca owns task state, retries and recovery. Commander does not wrap it in one of its own.

      Resume needs a name

      With no task IDs and no run key, Commander lists the candidates and asks you to name one — even when only one matches.
